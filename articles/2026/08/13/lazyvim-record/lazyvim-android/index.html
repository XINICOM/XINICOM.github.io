TL;DR

在 $env:LOCALAPPDATA\nvim\lua\plugins\kotlin.lua 下：

kotlin.lua | lang:lua
return {
    {
        "AlexandrosAlexiou/kotlin.nvim",
        ft = { "kotlin", "kt", "kts" },
        config = true,
        dependencies = {
            "mason.nvim",
            "mason-lspconfig.nvim",
            "trouble.nvim",
        },

    },
}

这会启用 AlexandrosAlexiou/kotlin.nvim 插件

IMPORTANT

不要使用官方 LazyExtras 下的 lang.kotlin 插件

简介

本文介绍如何在 LazyVim 中使用 kotlin-lsp 以辅助开发 Android 开发，
由于上述要求比只使用 kotlin 要高，故而可能对仅 kotlin 开发有一定帮助

值得注意的是辅助 Android 开发；开发除去编写代码的部分，可能使用 Android Studio 任然为最佳的选择

细节

必要的组件

如果你是从 Android Studio（后文简称 AS） 迁移到 LazyVim 里面的，或者你会同时使用上述两个软件，
那么最好使用 AS 来先行安装所有的环境，同时你可以尝试建立一个示例项目，测试能否在 AS 中正确的编译和部署

语言服务器

经过对 kotlin_language_server, kotlin-lsp 和 kmp-lsp 的测试：

  • kotlin_language_server 的功能已经过时，其无法解析 android 和 androidx 包，无法支持 Android 开发

    • 通过查看日志文件得知其使用的获取 Classpath 的方法已经过时
    • 尝试在其配置中更改 gradlepath 是无效的

  • kotlin-lsp 的功能完善

    • 直接使用无法跳转包内的对象的定义
    • 通过 K 快捷键进行 Hover 所显示的无语法高亮；对包中的仅包含头部信息（编译），对文件内的还会显示注释，但是均没有 @param 等细节

  • kmp-lsp 的功能较为完善

    • 直接使用无法跳转包内的对象的定义
    • 通过 K 快捷键进行 Hover 所显示的对包中的仅包含头部信息（编译），对文件内的还会显示注释，但是均没有 @param 等细节
    • Hover 会有部分的语法高亮

综上由于 AlexandrosAlexiou/kotlin.nvim 插件内部使用的是 kotlin-lsp 这个语言服务器，故而使用插件的选择（抛弃对 Hover 的语法高亮的支持）

TIP

使用上述插件后即可实现跳转到定义（包括跳转到包中的函数和类）
具体实现应该是将 class.jar 反编译
虽说这个反编译理论上本来也应该会实现，然而实际上若是没有插件直接使用 LSP，则会直接连接到 .jar 包内，导致跳转出错
另外，本插件依旧做不到 AS 使用 source.jar 的能力，在 Hover 时也无法提供 @param 之类的信息

format 和 lint

kotlin-lsp

若是使用 AlexandrosAlexiou/kotlin.nvim 插件则不会使用任何独立的格式化器和代码检查器，其功能由 kotlin-lsp 承担

kotlin-lsp 难以配置

kotlin-lsp 该语言服务器自带 lint 功能，且该功能难以配置，甚至难以关闭

这意味着，若使用该 LSP 和其他的独立审查器和格式化器，虽然 format 和 lint 的功能由独立组件承担，
然而依旧会因为 kotlin-lsp 无法配置，而显示不必要的审查报错或 warning，
这些报错不会和 ktlint 一样影响格式化的进行，仅是不美观

ktlint

若是使用官方的 lang.kotlin 插件则会使用 ktlint 来作为格式化器和代码检查器，
然而此官方插件会让 Mason 下载 kotlin_language_server 作为语言服务器，考虑到这个 LSP 的限制，一般来说这不是我们想要的

若你希望单独使用 ktlint 则可能会面临如下问题：

Parser failed. Error message:
...cal/nvim-data/lazy/nvim-lint/lua/lint/linters/ktlint.lua:8: Expected value but found invalid token at character 1
Output from linter:
'java'<${由于编码问题导致的乱码}……

上述是因为 ktlint 需要 Java 来运行，而其会需要有对应的环境变量

  1. 下载 Java 的 JDK
    可以访问 Adoptium JDK V17 进行下载

    JDK 版本要求

    因为在研究时并未马上记录，故而不确定对 JDK 的版本的要求限制在哪里
    当时似乎使用过 JDK25 但是失败了，似乎使用过 JDK21 成功了，据 AI 所言 JDK17 应该时可行的
    这里也放一下 Adoptium JDK V21 以供选择

  2. 在 $env:LOCALAPPDATA\nvim\lua\config\options.lua 中添加：

    options.lua(partial) | lang:lua
    -- Java 环境变量
vim.env.JAVA_HOME = "${这里改成你自己的 jdk 的位置}"
vim.env.PATH = vim.env.JAVA_HOME .. "\\bin;" .. vim.env.PATH
    环境变量

    LazyVim 内提示的环境变量可能不是指代系统的环境变量，而是仅属于 LazyVim 的变量

    虽然不推荐，但若是不想在 LazyVim 内添加环境变量也可以尝试在对应需要环境变量的组件的 .bat 或 .cmd 等启动文件内添加变量

其他问题

若是执意使用 kotlin_language_server 可能出现 Java JDK 问题，解决方法和上方解决 ktlint 的问题的方法一致

lsp.log | lang:txt
[START][2026-08-13 00:50:27] LSP logging initiated
[ERROR][2026-08-13 00:50:27] ...gram Files/Neovim/share/nvim/runtime/lua/vim/lsp/log.lua:150 "rpc" "kotlin-language-server" "stderr" " \r\nERROR: JAVA_HOME is not set and no 'java' command could be found in your PATH. \r\n \r\nPlease set the JAVA_HOME variable in your environment to match the \r\nlocation of your Java installation. \r\n"
